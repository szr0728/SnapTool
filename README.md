# SnapTool —— 截图工具（类微信截图）

Windows 截图工具，全局热键 **Alt+A**，常驻托盘，**单文件 59KB**，不依赖 Python、不打包 Qt、也不用装 .NET 8。
C# / WinForms + GDI+ 实现，运行时用 Windows 自带的 .NET Framework 4.8（Win10 1903+ / Win11 均内置）。

## 快速开始

1. 双击 `SnapTool.exe`（启动约 0.2 秒）
2. 托盘出现蓝色取景框图标，说明已在后台待命
3. 任意界面按 **Alt+A** 截图

> 建议：托盘右键 → 勾选「开机自启动」，以后开机就在托盘等着。

## 版本号

当前 **v1.1.0-beta**，测试阶段，交互与配置项仍可能调整。

- 托盘右键菜单第一行、托盘悬停提示、气泡标题、exe 文件属性（右键 → 属性 → 详细信息）都能看到版本
- 版本号只写在 `nf/SnapTool.nf.csproj` 的 `<Version>` 一处，程序运行时从程序集元数据读取，代码里没有硬编码
- 版本号后面跟的是**这次编译的时刻**（`MM-dd HH:mm`）—— 同一个版本号编译了多次也能分辨
- 带 `-beta` / `-rc` 后缀表示预发布，程序会自动标注「测试版」；把后缀去掉重新编译即为正式版

版本推进规则：加功能加第二位（1.1 → 1.2），修 bug 加第三位（1.1.0 → 1.1.1）。

## 标注工具

工具条从左到右：**4 个颜色**（红 / 黄 / 绿 / 蓝）→ **矩形 · 椭圆 · 箭头 · 画笔 · 文字 · 马赛克** → **撤销 · 保存 · 取消 · 完成**

- 选好工具后在选区内按住拖动即可绘制；标注超出选区的部分会被裁掉

## 复制时自动去掉公式定界符

从 AI 对话里复制数学公式，常常会带着一层 `\(` … `\)` 外包装，粘到别处就是错的。
程序常驻监听剪贴板，**整段**内容被定界符包住时自动剥掉，你直接粘贴就是裸 LaTeX。

| 复制到的内容 | 处理结果 |
| --- | --- |
| `\(o\left(x^m\right)\xlongequal{…}\)` | 去掉外层 → `o\left(x^m\right)\xlongequal{…}` |
| `\[E=mc^2\]` | 去掉外层 → `E=mc^2` |
| `$$\int_0^1 x^2 dx$$` | 去掉外层 → `\int_0^1 x^2 dx` |
| `\boldsymbol{\begin{cases}…\end{cases},\quad 0\le t\le 2\pi}` | **原样不动**（本来就没包装） |
| `设 \(f(x)\)，则 \(g(x)\)` | **原样不动**（正文里夹多条公式，动了会撕坏正文） |
| 普通文字 | **原样不动** |

判定规则（刻意保守，宁可不改也不改坏）：

1. 去掉首尾空白后，整段必须以某对定界符**开头并结尾**
2. 中间不能再出现同类定界符，否则判定为「多条公式混排」，不处理
3. `\(\` 与 `\\[6pt]`（换行+间距）这类转义写法按反斜杠奇偶判定，不会被误当成定界符

开关：**托盘右键 → 「复制时去掉公式定界符 \( \)」**，默认开启，切换立即生效并写入配置。
关闭后剪贴板完全不被触碰。

## 截图输出

- **默认**：复制到剪贴板（可直接粘贴到微信 / 飞书 / Word / 画图）
- **保存**：默认目录 `图片\Screenshots`，文件名 `截图_20261029_130000.png`
- `Ctrl+S` 保存的同时也会写入剪贴板

## 配置文件

`%APPDATA%\SnapTool\config.json`

```json
{
  "hotkey": "alt+a",
  "save_dir": "C:\\Users\\<你>\\Pictures\\Screenshots",
  "magnifier": true,
  "notify": false,
  "formula_fix": true
}
```

- `hotkey`：支持 `alt+a`、`ctrl+shift+x`、`f1` 等写法，改完重启生效
- `magnifier`：框选/缩放时是否显示 8 倍放大镜 + 十字准星
- `notify`：复制/保存后是否弹托盘气泡，`false` 为静默（托盘菜单可随时切换）
- `formula_fix`：复制整段 `\(…\)` 时是否自动去掉定界符，默认 `true`（托盘菜单可随时切换）

### 重新编译

**推荐：net48 版（59KB，当前安装的就是这个）**

```bash
cd nf
dotnet build -c Release -o out
```

产物 `nf/out/SnapTool.exe` 约 59KB，只需这一个文件；同目录生成的 `SnapTool.exe.config` 可以不要。

**备选：net8 版（210KB，需要 .NET 8 桌面运行时）**

```bash
dotnet publish SnapTool.csproj -c Release -r win-x64 --self-contained false -o dist
```

**编译环境**：任意版本的 .NET SDK（含 MSBuild）即可，不需要单独装 .NET Framework 4.8 SDK。
net48 目标会通过 NuGet 自动拉取 `Microsoft.NETFramework.ReferenceAssemblies` 参考程序集，首次编译需要联网。

## 为什么只有几十 KB

最初的 Python + PyQt5 原型是 22MB（代码已移除，这里只作对比）：要把 Python 解释器（4.2MB）和 Qt 图形库（17.6MB）整套塞进 exe。

换成 C# 后是 210KB，其中 **158KB 是微软固定的 apphost 启动壳**（负责找到并拉起 .NET 运行时），你自己的代码只有 52KB。
apphost 是 .NET Core / 5+ 的硬性开销，只要还想双击直接运行就删不掉。

改用 .NET Framework 4.8 目标后，exe 直接就是托管程序本身，没有启动壳，于是 **210KB → 54KB**（后来加了剪贴板公式清理，现在 59KB）。
副作用是反而更好：4.8 是 Windows 10 1903+ 和 Windows 11 的**系统组件**，无需另装运行时；启动也从 0.2s 降到约 0.1s。

### 还能再小吗

- `.NET Framework 3.5` 目标：约 40KB，但 Win10 默认不启用 3.5，会让用户遇到"需要下载功能"的弹窗 —— 不划算
- 换 C/C++ 或手写 Win32：理论 20~30KB，但要重新实现全部交互，且本机没有 C 编译器
- Go：最小 hello world 也有 1.3MB，**比现在还大**
- UPX 压缩：能到约 25KB，但会注册全局热键的程序几乎必然被杀软误报 —— 不建议

**59KB 基本就是这个形态的地板了。**

## 卸载

1. 托盘右键 → 取消勾选「开机自启动」→ 退出
2. 删除 `%LOCALAPPDATA%\SnapTool` 与 `%APPDATA%\SnapTool`

## 已知说明

- 多显示器：按虚拟桌面整屏抓取（物理像素 1:1），跨屏框选可用
- DPI：进程声明为 Per-Monitor V2，物理像素坐标，100%/125%/150% 缩放都不会偏移
- 热键被其他软件占用时，托盘会弹一次提示；改 `config.json` 的 `hotkey` 后重启
- 截图期间窗口独占键盘，`Esc` / `Enter` / `Ctrl+Z` 不会因为焦点被抢而失灵
- **托盘图标与 exe 图标同源**：运行时用 `ExtractIconEx` 从 exe 自己的图标资源里取，不是另外画一个，所以文件图标、任务栏、托盘三处必然一致
- **拉框过程中不显示工具条**（与微信一致），松开鼠标后出现在选区下方

## 拖动不卡是怎么做到的

早期版本拖框时每帧都重建整个底层图（`RebuildBg`：整屏拷贝 + 四次整屏填充），再加上重绘时两次整屏位图搬运，
1920×1080 下每个鼠标事件要搬约 33MB 内存，鼠标一快就明显掉帧。

现在的做法：

1. **整屏变暗图只生成一次**（打开遮罩时）。选区内部由绘制时单独用原亮度图层覆盖，选区变化不需要重建任何整屏图。
2. **增量重绘**：鼠标移动时只 `Invalidate(旧选区 ∪ 新选区 ∪ 旧工具条 ∪ 新工具条 ∪ 旧放大镜 ∪ 新放大镜)`，
   绘制时也只在脏区里做 1:1 搬运（`DrawImage(_bg, clip, clip, ...)`），开销与脏区面积成正比而不是与屏幕面积成正比。
3. **拉框时隐藏工具条**，省掉每帧重画 14 个按钮和圆角路径。
4. 字体改为构造时创建一次，不再每帧 `new Font`。

实测连续拖动 300 步、每步平均 CPU 1.7ms（此前是整屏级开销，鼠标越快越卡）。
